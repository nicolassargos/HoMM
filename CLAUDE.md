# HoMM – notes pour Claude

Jeu PC fortement inspiré de Heroes of Might and Magic / King's Bounty. L'utilisateur est francophone mais préfère échanger en anglais (un anglais simple et clair). Les textes du jeu, les commentaires, la documentation, les commits et les PR restent en français.

## Plan
La vision du jeu et les étapes prévues sont dans `PLAN.md`, importé ci-dessous. Le suivre pour chaque nouvelle fonctionnalité, et le mettre à jour quand les idées changent ou qu'une étape avance (cocher ✅, noter les décisions prises).
`PLAN.md` reste court : la direction, l'étape en cours et les choix encore valables. Le détail d'un travail fini (chiffres mesurés, essais écartés, classes et fichiers) va dans `HISTORIQUE.md` (non importé : le lire quand on a besoin du passé d'une partie du jeu). Avant un travail d'images, lire `tools/art/METHODE.md` et y noter ce qui marche ou non.

## Git
- Une branche par étape ou par sujet, créée depuis `main` à jour (`git switch main`, `git pull`, `git switch -c <nom>`). Noms en minuscules avec tirets (ex. `etape-2-villes`).
- Une PR de la branche **directement vers `main`** : pas de PR empilée sur une autre branche.
- Avant de proposer une PR : `dotnet test` réussi et `dotnet build` (dans `godot/`) sans erreur.
- Messages de commit et descriptions de PR en français.
- Après la fusion (faite par l'utilisateur) : revenir sur `main` et récupérer les changements (`git switch main`, puis `git pull`), avant toute nouvelle branche. L'utilisateur supprime lui-même les branches fusionnées.
- Ne pas fusionner une PR ni supprimer de branche sans l'accord de l'utilisateur.

## Choix techniques
- Godot 4.7.2 **édition .NET** + C# (.NET 8). Le projet est dans `godot/`.
- Utiliser l'éditeur Godot le moins possible : tout est construit par le code (scène unique `scenes/Main.tscn`).
- Les cartes doivent, à terme, être générées automatiquement (`MapGenerator`).
- Code : identifiants en anglais, commentaires et textes affichés en français.

## Organisation
- `godot/scripts/Core/` : règles en C# pur, **sans dépendance à Godot** (testables). Y mettre toute la logique de jeu.
- Règles → affichage : `GameState` ajoute des événements (type de base dans `GameEvents.cs`, chaque événement défini dans le fichier de ce qu'il concerne) que `Main` lit avec `TakeEvents()` et montre à son rythme. L'affichage ne modifie l'état qu'en appelant les méthodes de `GameState`. Toute nouvelle action visible (animation, fenêtre, son) passe par un événement. Les règles ne produisent aucun texte affiché : tout texte va dans `Game/Texts.cs`.
- `godot/scripts/Game/` : affichage, interface, commandes (Godot). Une classe Godot par fichier, nom du fichier = nom de la classe.
- `tests/HoMM.Core.Tests/` : tests xUnit des règles.
- Son : `godot/audio/` (fichiers .ogg, .wav ou .mp3, lus directement ; licences dans `godot/audio/LICENCES.md`), décrits dans `godot/data/sounds.json` ; joués par `Game/Audio.cs` (`Audio.Play`, `Audio.PlayMusic`, `Audio.PlayFor` pour un événement, `Audio.PlayCreature` au combat). Outils dans `tools/audio/` (`essai.py` : comparer ElevenLabs, Stable Audio et les sons libres ; `sons.py` : générer une liste chez ElevenLabs, une page de revue « bon / à refaire » qui enregistre seule, installer ; `pas.py` : les pas au combat, une marche par façon de marcher et par sol, coupée en pas seuls, une page où ils se jouent comme une marche ; les créatures de chaque marche dans `sounds.json` (« gaits ») ; `musiques.py` : écouter des musiques libres, les noter de 1 à 5 étoiles, choisir et installer ; `carte` : une par terrain, `menu` : parmi les 3 étoiles et plus qui ne servent pas ; `page tout` montre aussi les écartées ; « aussi » dans la liste : une piste jouée en plus de la choisie ; le serveur sert les fichiers par morceaux, pour que le curseur avance et que le navigateur ne bloque pas ; `ambiances` : une boucle par sol, section « ambience » ; `boucler.py` : couper, fondre la fin dans le début et mettre les ambiances à la même force, une fois après l'installation, avec numpy et soundfile). La musique de la carte suit le terrain autour du héros (`map-<terrain>`, sinon `map`), l'ambiance aussi (`Audio.PlayAmbience`) ; une clé de `sounds.json` peut avoir plusieurs fichiers, joués tour à tour au hasard.
- `prototype-python/` : ancien prototype, gardé pour mémoire, ne plus le faire évoluer.

## Services d'images (décision de l'utilisateur, 2026-11-04)
- **PixelLab** (`tools/art/pixellab.py`, clé dans la variable `PIXELLAB_API_KEY`) : les **personnages et créatures**
  (images de combat, animations), et des essais pour l'**interface**.
- **Retro Diffusion** (`tools/art/generer.py`, clé dans `RETRO_DIFFUSION_API_KEY`) : les **cartes** (terrains,
  décors, objets) et les **portraits** des héros humains.
- Ne jamais afficher ni écrire les clés. Montrer le prix avant de dépenser (Retro Diffusion : `cout`, gratuit ;
  PixelLab n'a pas d'estimation gratuite : `solde` avant et après) et attendre l'accord de l'utilisateur.

## Propositions d'images (dossier `art-candidats/`, non suivi par git)
Décision de l'utilisateur, valable pour toutes les sessions :
- `art-candidats/en-cours/` ne contient **que ce qui attend une réponse de l'utilisateur** : captures d'écran
  de comparaison (`jeu-*.png`), agrandissements (`zoom-*.png`), pages de choix, candidats générés pas encore
  choisis (`en-cours/candidats/<nom>/`, écrits par `tools/art/generer.py`).
- Une fois la décision prise, tout part dans `art-candidats/archives/AAAA-MM-JJ-sujet/` avec
  `python -I tools/art/archiver.py sujet`. Ne rien laisser traîner à la racine de `art-candidats/`.
- `art-candidats/references/` : images données par l'utilisateur (modèles, captures), à garder telles quelles.
- Outils : `tools/art/generer.py` (prix, génération, choix ; `choisir` retrouve aussi un candidat archivé),
  `tools/art/apercu.py` (page de choix dans `en-cours/`), `tools/art/page_choix.py` (la page où l'on clique pour choisir dans n'importe quel lot, animations comprises ; réponses écrites par `revue.py serveur`), `tools/art/revue.py` (page de revue où l'on choisit et commente chaque image, une par lot de candidats : `32px`, `v2` ; `serveur` écrit les réponses sur le disque, `appliquer` les installe), `tools/art/zoom.py` (agrandir une capture),
  `tools/art/pieds.py` (les pieds des images de la carte pour l'ombre de contact : `proposer`, `page` de revue où l'on corrige les points, `appliquer` ; écrit `godot/art/pieds.json`),
  `tools/art/empreintes.py` (les cases que bloque chaque massif de montagnes, d'après son image : écrit `godot/data/mountains.json`), `tools/art/recadrer.py` (couper une image à son dessin), `tools/art/fondre.py` (les pentes d'une montagne aux couleurs d'un sol de la carte, leur bord en trame), `tools/art/adoucir.py` (adoucir un contour noir ; un 6e nombre adoucit aussi les traits sombres de l'intérieur), `tools/art/affiner.py` (ramener à 1 px les traits sombres de 2 px de PixelLab), `tools/art/agrandir.py` (élargir une image générée : PixelLab peint les bords par morceaux de 200 × 200 ; le fond d'une scène de ville de 792 × 241 à 960 × 270), `tools/art/ville_scene.py` (la scène d'une ville peinte, mise dans le jeu : `godot/art/towns/<faction>/`, d'après le dossier des bâtiments peints),
  `tools/art/sans_socle.py` (retirer la tache d'herbe et l'ombre ovale sous un arbre généré, garder le trait des racines, couper les rangées vides du bas ; `--buisson` pour un buisson, `--sable` pour la tache de sable d'un arbre du désert), `tools/art/sans_disque.py` (le disque de sol peint sous un objet généré, fondu dans le sol sombre de la terre brûlée, le feu gardé ; `--sombre` pour un tas de rochers), `tools/art/blanchir.py` (blanchir au soleil : du bois sec, gris chaud, à partir d'une souche moussue ; garde l'ombrage), `tools/art/luminosite.py` (`mesure` : la luminosité moyenne d'images ; `regler` : éclaircir ou assombrir une image jusqu'à une luminosité, par une courbe ; `--garder-sombres` : les tons sombres ne bougent pas), `tools/art/reduire.py` (réduire ou retourner une image sans la flouter), `tools/art/cadre.py` (rendre transparent le
  centre uni d'un cadre généré), `tools/art/detourer.py` (rendre

## Commandes
- Tests : `dotnet test` (à la racine)
- Mesures de l'équilibre (simulation seule, adversaires à chaque niveau, courbe du Château ; toujours les mêmes graines, pour comparer avant et après un changement) : `HOMM_MESURES=1 dotnet test --filter Category=Mesures --logger "console;verbosity=detailed"` (`tests/HoMM.Core.Tests/MesuresTests.cs` ; ignorées par un `dotnet test` ordinaire). Y ajouter une mesure plutôt qu'écrire un test jetable. L'équilibre des factions : `Armees_a_prix_egal` (la mesure qui compte : une armée entière contre une autre ; `HOMM_FACTION=nains` pour une seule faction), celui des créatures d'un niveau : `Duels_a_prix_egal`.
- Disposition d'un écran, à la souris : `python -I tools/ui/disposition.py town` (écrit `godot/data/layouts/town.json` ; `town-xxx` : une autre disposition à comparer, lue en jeu avec `-- --layout=town-xxx`)
- Captures de tous les écrans (avant une PR d'interface, puis les regarder) : `python -I tools/captures.py` (ou `… ville` pour une partie), dans `art-candidats/en-cours/revue/`
- Lire des cartes de Heroes 2 et 3 (dans `maps references/`, non suivi) pour en tirer des règles : `tools/cartes/` (voir son `LISEZMOI.md`)
- Page des artefacts (chacun avec son image et ses effets, par rareté ; à relancer quand ils changent) : `python -I tools/docs/artefacts.py` (écrit `docs/artefacts.html`)
- Compiler : `dotnet build` (dans `godot/`)
- Lancer : `godot\lancer.bat` (Godot attendu dans `C:\Godot\`) : le menu principal ; toute option (ou `-- --play`) entre directement dans une partie ; plein écran (F11 ou Alt+Entrée : fenêtre agrandie ; `-- --windowed` pour démarrer en fenêtre), option `-- --seed=42` pour une carte fixe, `-- --load` pour reprendre la dernière sauvegarde, `-- --mute` sans aucun son (les captures sont toujours muettes)
- Mettre le dossier à jour puis montrer le jeu : `godot\demo-a-jour.bat` (tire `main` depuis GitHub, seulement si le dossier est sur `main` sans fichier suivi modifié, puis lance `demo.bat`)
- Montrer le jeu : `godot\demo.bat` (ou l'option `--demo`) : le menu principal, on choisit sa faction et son héros dans Nouvelle partie ; or et ressources sans fin, tous les bâtiments dans la ville du joueur (habitations pleines, sorts de la guilde), sans brouillard
